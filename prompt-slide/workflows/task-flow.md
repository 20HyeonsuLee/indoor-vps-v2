## 목적
slide 작업 entry. 요청 → plan → draft → review → finalize → 발표 lifecycle.

## 5 단계
1. **요청 접수**
   - 요청자·목적·청중·시간·deadline·output 형식 확인
   - 단순 요청도 issue 또는 task ticket으로 trail (선택)
2. **plan** (`workflows/plan`)
   - 목적·청중·핵심 메시지(big idea) 결정
   - deck 종류·길이 정함
   - storyboard (각 슬라이드 1줄 메모) 작성
3. **draft** (`workflows/draft`)
   - storyboard 기반 슬라이드 작성
   - master/template 적용
   - 시각·차트·이미지 채움
4. **review** (`workflows/review`)
   - self-review (5초 rule)
   - peer review 1+
   - stakeholder review (필요 시)
   - dry-run timing
5. **finalize** (`workflows/finalize`)
   - 최종 수정
   - export (pptx + pdf)
   - 공유 (email · cloud · 발표 환경 backup)
6. **rehearse + 발표** (`workflows/rehearse`)
   - timing 실측
   - Q&A 시뮬레이션
   - 백업 plan

## 분기 (deck 종류별)
| 종류 | 추가 절차 |
|---|---|
| executive briefing | pyramid top-down · 5초 rule 엄격 |
| technical deep-dive | bottom-up 가능 · 백업 슬라이드 충분 |
| sales pitch | Problem→Solution→Proof→Ask · CTA 명확 |
| training | step-by-step · 연습 시간 · 핸드아웃 |
| conference talk | story arc · signature slide · timing 엄격 |

## 항상 적용
- 목적·청중·메시지 확정 없이 작성 시작 X
- master/template 사용 (직접 디자인 X)
- 1 슬라이드 1 message
- a11y (`accessibility/a11y`)
- brand 일관 (`branding/brand`)

## 금지
- plan 없이 draft 시작
- review 0회로 외부 공유
- final 직전 큰 변경
- 발표 직전 export (사전)
- backup 단일 (USB만 또는 cloud만)
- sensitive 정보 마스킹 누락
