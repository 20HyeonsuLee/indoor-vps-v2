## 목적
final deck을 실제 발표 환경에서 dry-run + Q&A 준비.

## 절차
1. **timing dry-run**
   - 실제 발표 환경(시간·청중·tone)으로 처음부터 끝
   - 슬라이드별 timing 기록
   - 목표 시간 ± 10% 안 (초과 시 cut, 부족 시 보강)
   - PowerPoint 발표 시간 기록 기능 (`슬라이드 쇼 > 시간 기록`)
2. **Q&A 시뮬레이션**
   - 청중 관점 예상 질문 10+ 적기
   - 각 질문 1줄 답
   - backup 슬라이드로 답할 수 있나 검토
   - "모르겠다" 답변도 정직하게 (조작 X)
3. **발표 환경 검증**
   - projector/모니터 해상도
   - HDMI/USB-C 어댑터
   - 폰트 호환 (다른 PC)
   - 동영상·embed 동작
   - 인터넷 의존 콘텐츠는 offline backup
4. **발표자 노트 정리**
   - 슬라이드별 핵심 1줄
   - transition 멘트
   - 데이터 출처·세부 (질문 대비)
5. **delivery 점검**
   - 발성·속도 (1분에 ~120 단어)
   - eye contact
   - 자세
   - pause (강조 슬라이드 후)
6. **백업 plan**
   - 노트북 fail → 본인 phone에 PDF
   - projector fail → 핸드아웃 인쇄
   - 동영상 fail → 정적 이미지 또는 설명
   - 인터넷 fail → offline 콘텐츠
7. **발표 직전 (당일)**
   - 30분 전 도착·setup
   - mic·물·timer 준비
   - 첫 슬라이드 표시 + standby
   - 호흡

## 발표 중 원칙
- 슬라이드 읽지 X (청중이 더 빠르게 읽음 — 부연 설명만)
- backup·detail은 질문 받을 때 노출
- timing 초과 시 ahead skip (덜 중요 슬라이드 식별 미리)

## 사후
- 발표 자료 공유 (final PDF + 1줄 핵심)
- 받은 질문·feedback 기록 (다음 deck 개선)

## 금지
- dry-run 0회 외부 발표
- timing 미측정
- Q&A 준비 없이
- 환경 검증 없이 (당일 setup 실패 risk)
- 단일 backup
- 발표 중 슬라이드 그대로 읽기
- 청중 무시하고 슬라이드만 보기
- "다음 슬라이드..." 매번 (transition 자연스럽게)
- 시간 초과로 핵심 메시지 생략 (priority 미리)
- sensitive 정보를 백업에 평문
