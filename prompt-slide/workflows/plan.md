## 목적
draft 시작 전 **목적·청중·메시지**를 확정하고 **storyboard**를 만든다.

## 절차
1. **목적 1줄**
   - "이 deck으로 청중이 무엇을 결정·이해·행동하게 할 것인가?"
   - 예: "Q4 매출 23% 증가의 원인을 임원진에 설명하고 Q5 예산 승인 받기"
2. **청중 분석**
   - 누구 (직책·도메인 지식·관심사)
   - 사전 지식 수준
   - 결정권자 vs 영향자
   - 관심 vs 무관심 시작점
3. **big idea 1 문장**
   - deck 끝에 청중이 기억할 1 문장
   - 검증 가능·구체적·청중 언어
4. **deck 종류·길이**
   - executive/technical/sales/training (`structure/deck`)
   - 시간 × 2 = 슬라이드 수 권장
5. **arc 패턴 선택** (`structure/flow`)
   - SCQA / Pyramid / Problem-Solution / Why-What-How 등
6. **storyboard 작성**
   - 슬라이드별 1줄 헤드라인 (결론) + 시각 아이디어
   - 보통 종이 또는 markdown으로 빠르게
   - 슬라이드 순서 검증: "왜 다음 슬라이드가 이거?" 자연스러움
7. **검토 (plan review)**
   - 요청자·stakeholder에 storyboard 공유
   - big idea·arc·길이 합의
   - draft 진입 전 sign-off

## 산출물
- plan 1 page (목적·청중·big idea·종류·길이·arc)
- storyboard (슬라이드 N개의 headline + 시각 메모)

## 금지
- plan 없이 draft (요청 받자마자 PowerPoint 열지 X)
- big idea 모호 ("...에 대해 발표")
- 청중 분석 누락
- arc 패턴 없이 슬라이드 순서 random
- storyboard 0 슬라이드 (그냥 머릿속)
- plan review 없이 draft (큰 변경 risk)
- 시간·deadline 무시
- 청중과 무관한 슬라이드 포함
