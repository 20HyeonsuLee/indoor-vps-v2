## rule
- 슬라이드 deck은 **목적·청중·메시지** 3개부터 정한다. 이 3개 없이 슬라이드 만들기 금지.
- deck 길이는 발표 시간에 맞춤: **1분당 1~2 슬라이드** (자세한 차트는 더 길어짐).
- 표준 구조 (변형 가능):
  1. **표지** (제목·발표자·날짜·로고) — 1장
  2. **목차/agenda** — 1장 (5장 미만 deck은 생략 가능)
  3. **intro/문제 정의** — 1~3장
  4. **본문** — 청중·목적별 (`structure/flow.md` 참조)
  5. **결론/요약** — 1장 (핵심 메시지 재강조)
  6. **CTA/next step** — 1장 (제안서·세일즈)
  7. **Q&A·감사** — 1장
  8. **백업/appendix** — 필요 시
- deck 종류별 표준:
  - **executive briefing**: 5~10장. 결론 먼저 (top-down). 데이터는 backup
  - **technical deep-dive**: 15~30장. 단계별 설명
  - **sales pitch**: 8~15장. Problem → Solution → Proof → Ask
  - **training/tutorial**: 20~40장. step-by-step + 연습
  - **status report**: 5~10장. 진행·issue·next
  - **conference talk**: 15~30장. story arc + signature slide
- deck 파일명: `<YYYY-MM-DD>_<topic>_<audience>.pptx` (예: `2026-05-24_indoor-vps_executive.pptx`).
- 슬라이드 번호는 표지·Q&A 제외하고 표시.
- 모든 슬라이드에 일관 footer (회사·날짜·페이지) 또는 master에서.

## forbidden
- 목적·청중·메시지 정하지 않고 슬라이드 작성 시작
- 시간 무시한 슬라이드 수 (10분 발표에 50장)
- 표지·결론·목차 없이 본문만
- 같은 deck에 청중·목적 다른 슬라이드 혼재 (분리)
- 슬라이드 번호 누락
- 본문에서 갑자기 톤 변경 (전체 일관)
- 4가지 이상 색조 사용 (1 deck = 제한된 팔레트)
- backup 슬라이드를 본문에 섞음
- deck 길이 무계획 (목적·청중 기준 cap)
- 발표 시간 측정 없이 final
