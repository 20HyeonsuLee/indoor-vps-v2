## rule
- 로깅 facade는 **SLF4J**. logback이 구현체. log4j 직접 사용 금지.
- logger 선언: `private static final Logger log = LoggerFactory.getLogger(<Class>.class);` 또는 Lombok `@Slf4j`.
- log level 정책:
  - `ERROR`: 즉시 조치 필요한 시스템 실패. 5xx 응답·외부 호출 실패. 풀스택트레이스
  - `WARN`: 비정상이지만 자동 복구. 도메인 invariant 위반(4xx) 등
  - `INFO`: 비즈니스 이벤트(주요 UseCase 진입·완료). 로그인·결제 같은 trail
  - `DEBUG`: 개발 디버깅. prod 비활성
  - `TRACE`: 매우 상세. 거의 미사용
- 메시지는 **placeholder 사용** (`log.info("user {} created at {}", userId, createdAt)`). String concat 금지(`+`).
- 로그는 **구조화(JSON)**. 환경별 encoder 분리(local = pretty, prod = JSON).
- MDC로 컨텍스트 주입: `traceId`, `userId`, `requestId`. Filter/Interceptor에서 set·clear.
- 민감 정보(password, token, PII)는 **마스킹** 또는 로그 X. `User user` 통째 로깅 금지(toString 누출).
- 예외 로깅은 `log.error("message", exception)` (마지막 인자 throwable). 메시지에 `e.getMessage()` 끼우는 패턴 X.
- 외부 호출·DB 쿼리 로그는 sampled (TPS 높으면 rate limit).
- log 파일은 컨테이너 stdout/stderr로. 호스트 파일 시스템 직접 write X (compose log driver가 수집).
- `application.yml`에 root level 기본 `INFO`. 패키지별 override 가능 (`logging.level.kr.ac.koreatech.indoor.vps: DEBUG`).

## forbidden
- `System.out.println` / `e.printStackTrace()` (production 코드)
- log4j 직접 사용
- String concat 메시지 (`"user " + userId + " created"`)
- 민감 정보 평문 로깅
- toString 통한 도메인 객체 통째 로깅 (의도 누락 + PII risk)
- 한 줄에 여러 정보 융합 (구조화 깨짐)
- `log.error` 메시지에 `e.getMessage()` 끼움 (throwable은 인자로)
- 호스트 파일 시스템 직접 write
- DEBUG/TRACE를 prod에 활성
- MDC clear 누락 (요청 간 컨텍스트 leak)
- 로그 메시지 안 `printf` 스타일 `%s` (SLF4J placeholder `{}` 사용)
- catch 후 swallow하고 로그도 안 남김
