## rule
- fetch type 기본 **LAZY**. `@ManyToOne`, `@OneToOne`도 명시적으로 `fetch = LAZY` (기본이 EAGER인 경우 회피).
- N+1 차단:
  - 단건 조회 시 필요한 연관은 `@EntityGraph(attributePaths = ...)` 또는 fetch join.
  - 목록 조회 시 batch_size 설정 (`spring.jpa.properties.hibernate.default_batch_fetch_size: 100`).
  - 같은 호출 안에서 lazy collection을 N번 접근하면 fetch join 또는 batch fetch.
- **OSIV(Open Session In View) off**. `spring.jpa.open-in-view: false`. UseCase 트랜잭션 경계 밖에서 lazy access 발생 차단.
- `@Transactional`은 UseCase 메서드만. Repository/도메인 객체에 직접 부착 금지.
- read-only 쿼리는 `@Transactional(readOnly = true)` — flush mode·dirty checking skip.
- dirty checking 의존 시 명시: 변경 후 별도 `save()` 호출 안 해도 트랜잭션 commit 시 update SQL 발생함을 README/주석 또는 메서드명으로 표현.
- `EntityManager`/`@PersistenceContext` 직접 사용 금지. Spring Data Repository 또는 RepositoryCustom 인터페이스 경유.
- Aggregate 간 관계는 ID 참조만 (`FloorId floorId`). `@ManyToOne Floor floor` 객체 참조 금지 (architecture/domain/domain/entity.md 참조).
- Aggregate 내 관계는 `@OneToMany(cascade = ALL, orphanRemoval = true)` + 양방향 동기화 메서드 (`addChild()` 내부에서 `child.setParent(this)` 호출).
- 식별자 전략은 VO `@EmbeddedId` 또는 `@Id` + DB-generated. application-generated UUID는 `@PrePersist`에서.
- batch insert는 `spring.jpa.properties.hibernate.jdbc.batch_size: 100` + sequence allocator(IDENTITY는 batch 불가).
- equals/hashCode는 identity 기반(ID 비교). 양방향 관계 entity에는 collection 포함 금지(`StackOverflow`).
- soft delete는 `@SQLDelete` + `@Where`. 명시적이지 않으면 hard delete.

## forbidden
- fetch type EAGER (명시적이든 기본값 의존이든)
- OSIV `true`
- Repository/도메인 객체에 `@Transactional`
- `EntityManager` / `@PersistenceContext` 직접 사용
- Aggregate 간 객체 참조 (`@ManyToOne Floor floor`)
- 양방향 관계의 entity equals/hashCode에 collection 포함
- N+1 패턴 미인지 (`stream + map`으로 lazy collection 접근하는 패턴 review 필수)
- `getReferenceById` 무분별 사용 (proxy를 외부에 노출하면 lazy fetch 누락 risk)
- `nativeQuery = true` 남용 (JPQL/Spring Data 메서드명 우선)
- `JOIN FETCH`로 컬렉션 + paging 조합 (메모리 위 paging 발생)
- `@OneToMany`로 다른 Aggregate Root 묶기 (경계 위반)
- Entity의 setter 노출 (Tell Don't Ask 위반)
- IDENTITY 전략 + batch insert (실패 — sequence/table 전략 사용)
